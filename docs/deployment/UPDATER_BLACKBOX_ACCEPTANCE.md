# Updater mock 黑盒验收

验收日期：2026-09-21。对应 PR：[#562](https://github.com/Myriad-You/Myriad/pull/562)。

**最终结果：本报告所列 mock 升级与中断恢复场景全部通过。** 19 项进程级黑盒测试通过，包含 16 项 updater API 测试和 3 项 helper 测试。此前切换 tag 后、新服务启动后重启进入 `needs_manual` 的两处失败已修复；现在断言自动完成或恢复旧部署，不再用“复现失败成功”代替验收。

## 目的与方法

验证从更新请求开始，到正常完成、突然中断、再次启动和失败回滚，最终版本、编排、数据、任务记录与维护状态是否一致，是否需要用户补做操作。

测试运行编译出的真实 updater/helper，通过 HTTP 提交请求。选版、任务落盘、Compose 合并、版本切换、快照复制/恢复、启动恢复和结果写入均执行生产代码。Compose 配置使用真实 Docker Compose CLI 解析；Docker API、容器执行、镜像仓库和应用健康响应使用测试替身。内置数据库模式使用真实临时目录与文件复制，模拟初始化器修改数据后失败。

中断用例先让真实流程到达停止服务、复制快照、切换 tag、启动新服务或恢复数据等外部操作，再向 updater 及其 Compose 子进程组发送 `SIGKILL`。随后保留同一份部署文件和状态，重新启动。故障注入位于测试替身，生产代码没有测试开关；这些演练不预先编造恢复任务。

## 如何运行

需要 Linux、仓库支持的 Rust 工具链、Docker Compose CLI、bash、sed 和 GNU coreutils。黑盒测试不需要 Docker daemon、真实镜像仓库凭据或正在运行的 Myriad 部署。

从仓库根目录运行：

```sh
cd updater
cargo test --locked --test component_update_api --test self_update_handoff -- --nocapture
```

运行整个 updater 检查：

```sh
cd updater
cargo test --all-targets --locked
cargo clippy --all-targets --locked -- -D warnings
```

默认测试共 361 项通过，7 项带运行条件的测试默认跳过。本次另行运行这 7 项也全部通过，其中包括 v0.5.3 原始 Compose 的业务升级配置和 helper 升级/回退兼容检查；合计 368 项 Rust 测试通过。Clippy、8 项部署兼容检查及脚本语法检查也通过。补跑需要 Docker CLI/Compose 与可访问的 Docker daemon：

```sh
cd updater
cargo test --lib --locked -- --ignored
```

## 旧编排缺少 media 挂载的修复

旧流程只切换 `MYRIAD_TAG`，继续使用宿主原有 Compose。目标版本的联邦上传需要写入 `/app/data/media`，旧编排只有只读数据根目录而没有该可写子挂载时，预检拒绝更新并要求用户修改部署文件。可写路径确有用途；“挂载总数必须恰好为 5”不是业务要求，也无法完成部署迁移。

现在发布流程把同一源码版本的内置/外置数据库模板放进 backend 镜像标签。更新器从已拉取的目标镜像读取对应模板，用 Compose 自身解析配置，更新业务服务定义并保留站点配置。模板仍以仓库中的两份部署文件为来源，没有另维护一套目录映射，也不增加独立 SHA256 校验或新镜像对 GitHub Release 下载的依赖。

已有可信 helper 自动把宿主 Compose 入口迁为指向 `state/compose/` 的相对链接，入口名称不变。更新器通过既有可写 state 挂载替换内容；部署根和 Guard 策略继续只读，不要求用户重新挂载整个根目录。业务更新不替换 proxy、updater、Guard、gateway 或数据库服务定义。

目标镜像、变更前后编排在停服前持久化。失败回滚同时恢复旧编排、版本和内置数据库快照；重启复用同一启动/回滚路径。删除重复的联邦挂载数量预检，以及按旧 Compose 文本是否含 `${MYRIAD_TAG}` 拒绝更新的扫描。面板已经展开的旧镜像 tag 也能由目标模板自动迁移；容器权限仍由 Guard 执行。

兼容基线为最新已发布版本 v0.5.3。旧 Guard 可以调用新 helper 完成入口迁移；没有内嵌模板的旧目标按镜像源码 revision 获取并缓存模板；没有持久化准备结果的旧更新任务使用原回滚路径。过渡代码旁已注明在本次重构发布后的下一版移除。

## 证据边界

这是进程突然终止的 mock 演练，不是物理断电试验。没有模拟磁盘缓存丢失、文件系统损坏或真实 Docker 主机重启；数据库文件复制不能代替真实 PostgreSQL 迁移验证，worker 的模拟启动也不能代替真实联邦上传。Guard/helper 三组件整体自更新期间的主机断电未在本报告验收。

v0.5.3 在进程测试中是起始版本标记，另有原始发行 Compose 的解析兼容测试；这两项不等于完整 v0.5.3 发行二进制部署的端到端升级。真实发布镜像构建、推送及实际部署不属于本轮执行。
