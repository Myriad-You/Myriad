# 媒体资产：备份、恢复与旧目录

持久媒体在 `DATA_DIR/media`（compose 里是 `backend_data` 的 `media` 子路径）。
外链抓取缓存在 `CACHE_DIR/images`（`backend_cache`），可再生，不进灾备。

新上传、生成、编辑和联邦附件都写入媒体服务。Web 进程提供公开与鉴权读取；
联邦 worker 停掉不影响本站媒体。历史 `/media/federation/…` 与
`/api/phantasi/image-cache/…` 只通过已登记别名读取，不再从请求 URL 拼接磁盘路径。

## 显示地址

存储和对外发布的规范地址仍是 `/media/assets/…`、`/media/federation/…`。
站内页面显示时改走 `/api/media/assets/…`、`/api/media/federation/…`，由同一套公开读取处理。
proxy 只在管理员显式更新时升级；0.5.2 之前的 proxy 会把 `/media/assets` 交给前端 SPA，
把 `/media/federation` 交给联邦 worker（出口地区关闭联邦时不可达），而任何版本都转发 `/api/`。
外部读者（联邦对端、RSS 阅读器）拿到的仍是规范地址，这部分需要更新 proxy。

## 备份与恢复

与 [BACKUP.md](BACKUP.md) 相同：Postgres + `backend_data` + `.env`。
不要挂 `backend_cache` 当恢复条件。生成图、人设、贴纸、手帐上传和联邦附件
应能从数据卷里的 `media/` 读回。旧公开地址靠别名，不靠缓存卷。

回滚到理解新资产模型的版本。不能拿任意更旧的二进制直接对着新库启动。
扩展阶段若仍保留旧列和旧目录，可回到兼容读的版本；新写入切换之后不行。

## 不要做的事

- 启动时扫描整个 `federation_media` 或 `cache/images` 当常规写入。
- 部署脚本里 `rm -rf` 清旧媒体目录来「完成迁移」。
- 把 image-cache 当永久素材备份。
- 未另行授权就对生产做破坏性迁移或删除旧副本。

## 自动迁移旧媒体

升级后无需手动触发。Web 进程（开发环境的 all 角色亦同）启动后台迁移任务，
数据库连接就绪后每 5 秒尝试推进一批，
每批最多处理 50 条。迁移不阻塞服务启动，游标保存在 `media_migration_jobs`，
进程重启后自动续跑。多个副本通过数据库非阻塞锁协调，同一时间只有一个副本推进。
同一修订完成后不再扫描或复制；升级到修正迁移逻辑的新修订时会自动重新核对。
联邦和人设 worker 不承担迁移。

先分页取记录 ID，再逐条锁定并读取最新内容；被占用的记录进入重试队列，
不预先锁住整批业务记录。关联资产锁等待上限为 250 毫秒。
每批按 20 秒时间预算在记录之间让出；单个大文件允许完成，避免反复回滚同一批。
单条记录失败只回滚该记录，错误单独持久化，游标继续推进，正常记录照常完成。
整轮结束仍有失败时，按 1、2、4、8…分钟退避，最长间隔 1 小时；
之后只处理失败队列及其新发现的资产，不重扫正常历史记录。
已迁移文件不重复复制。批次本身失败则保留原游标重试。
错误与下次重试时间持久化，重启不会绕过同一修订的退避。
缺失文件不会被当作成功，也不会触发删除旧副本；修复源文件后下次重试自动继续。
仍有失败记录时 `complete=false`，旧资产的引用完整性保护不会解除。
数据库暂不可用时约每分钟重试连接后的工作。

管理员 API 仅用于检查和人工干预，不再是迁移前提：
`GET /api/media/migration` 查看进度；`POST /api/media/migration`（JSON `{}`）
立即重试一批，绕过退避；`{"restart":true}` 从头重新核对。
接口仍受管理员鉴权保护，不接受任意目录或 SQL。

返回的 `progress` 包含：

- `pass`：0 为发现引用并登记旧资产身份，1 为复制和校验文件，2 为登记业务引用。
- `phase` 与 `after`：当前消费者阶段和游标；初次扫描按原生主键分页，重试按工作队列键分页。
- `scanned`：累计处理记录数；同一消费者在发现和引用阶段分别计数。
- `complete`：只有全部阶段成功才为 true。
- `error`、`error_source`：脱敏错误码和失败的表名/记录 ID。
- `revision`：迁移逻辑修订号；旧修订即使已完成，也会自动补跑。
- `retrying`：是否已进入仅处理工作队列的阶段。
- `pending_failures`：尚未解决的记录数，包含为重试补充的发现/复制依赖（按阶段计数）。
- `consecutive_failures`、`next_retry_at`：连续失败轮次/批次与下次自动重试的 Unix 时间（秒）；扫描仍在推进时重试时间为空。

失败信息同时写入服务日志。可根据 `error_source` 定位缺失文件或错误数据；
自动重试期间无需持续发送请求。人工重扫保留已迁移文件和资产身份。
完整的逐条错误保存在 `media_migration_jobs` 的 `source_kind=upgrade_failure` 记录中。
旧 `brew` 与 `phantasi` 缓存地址共用历史别名；已有重复目录记录保留各自 ID，避免破坏现有引用。
存量贴纸的资产发布、公开地址回写和引用登记在同一事务中完成。

迁移先登记引用到的旧缓存文件，再复制已登记文件，最后核对手帐草稿/发布/历史、
人设、贴纸、RSS 中已入库资源的引用、联邦本地活动/待投递队列、未过期 AI 结果、
可读渠道消息和 Agent 历史。普通 RSS 下载缓存不自动转成永久资产；
订阅抓取和 Agent 订阅会原子登记已入库资源的引用，删除订阅源时一并释放。
不扫描无引用的缓存目录；加密渠道消息不在宿主解密。未知或未迁移资产保持删除保护。
迁移期间新增或改写正文如引用尚未迁移的本地地址，会返回 `MEDIA_NOT_READY`；
完成迁移后重试该业务保存。本站绝对地址仅按配置的站点 origin 识别，外站同路径不导入。

完成后验证旧地址与新地址均可读取，再按备份流程备份 Postgres 与数据卷。
恢复验收应在不挂缓存卷的环境中进行。旧源文件不会被迁移自动删除。
迁移复制使用资产身份对应的临时文件，续跑只清理该资产的未完成副本；
文件发布后同步目录元数据。进程在文件发布和数据库提交之间退出时，
续跑会校验已存在文件并沿用原身份，不重复建档。

## 自动恢复

现有进程维护循环每分钟最多恢复 16 个过期暂存资产，并重试最多 16 个删除中资产。
循环随进程退出取消，不额外创建永久后台进程。数据库断开时等待下一次维护。
写入每 200 秒续租；最终发布文件前持有资产行锁并核对写入令牌与租约。
过期 writer 被恢复任务接管后不能再发布文件。删除失败保留 `deleting`，后续维护重试。

## 回归测试

在可丢弃的 PostgreSQL 库上设置 `MYRIAD_MEDIA_TEST_DATABASE_URL` 后运行：

```sh
cargo test -p myriad-backend services::media:: -- --nocapture --test-threads=1
cargo test -p myriad-phantasi-notes
```

数据库测试各自创建独立 schema 并在成功后删除，不依赖现有业务数据。
未设置该变量时数据库测试会跳过，不能据此声称已完成数据库验收。


## 媒体目录分页

管理员 `GET /api/media` 每页默认返回 48 条，`limit` 范围为 1–100，按创建时间和 ID 倒序排列。响应包含 `items`、`next_cursor`；首个页面另有匹配当前筛选的 `total`，用于概览统计。

下一页传入 `next_cursor.created_at` 和 `next_cursor.id`，参数名分别为 `before_created_at`、`before_id`。时间字符串应原样传回，保留微秒精度；`next_cursor: null` 表示结束。筛选条件改变时应从第一页重新开始。

`kind` 支持 `all`、`upload`、`generated`；`format` 支持 `all`、`jpeg`、`png`、`gif`、`webp`、`mp4`、`webm`、`mov`、`other`；`query` 对文件名、MIME 和来源作不区分大小写的字面子串匹配。引用标签仅统计当前页资产的未过期引用。
