# 私聊通道的授权与运行生命周期

QQ、Telegram、Discord DM 和飞书私聊共用 Work 入口。平台适配器解析发送者、对话地址和消息 ID；绑定层把发送者解析成站内用户；Work 服务负责权限、额度、会话与执行；投递层把已有 run 的结果送回原对话。

## 模块边界

| 责任 | 实现入口 |
| --- | --- |
| 配对码签发、兑换、解绑、别名 | `backend/src/services/channel_pairing.rs` |
| 当前绑定与代次校验 | `backend/src/services/channel_pairing/binding.rs` |
| 输入准入、命令、续答 | `backend/src/services/channel_work.rs` |
| 短期会话锁、执行观察、恢复与撤销 | `backend/src/services/channel_work/runtime.rs` |
| 原子投影、逐项投递与重试 | `backend/src/services/channel_work/delivery.rs` |
| Work 事件到通道交互的映射 | `backend/src/services/channel_work/presentation.rs` |
| 平台 HTTP 与媒体下载 | `backend/src/services/channel_work/transport.rs` |

平台 token 仅存在于后端运输对象中。持久化地址不含 token，恢复时从当前配置重新解析。平台用户 ID 和 chat ID 各有用途：前者用于授权，后者只用于路由，不能互相替代。

## 配对是可撤销的授权前提

配对使用 `user_identities`，但这些记录不能登录，也不能充当最后一种 OAuth 登录方式。`discord_dm` 与 OAuth 的 `discord` 是不同 provider。登录、解绑 OAuth、禁用本地登录和头像选择必须排除所有通道 provider。

绑定记录带有当前 bot 凭据范围的摘要；会话、待答、入站去重和出站记录使用包含绑定代次的键。同一平台账号解绑后重新配对，即使回到同一个 Myriad 用户，也获得不同代次，无法继承旧的待答或结果。飞书同一身份的别名共享一个代次。

签发配对码、兑换和解绑共享数据库事务锁。兑换在锁内消费一次性码，避免解绑提交后，已经读到旧码的消息又创建授权。别名补全必须以仍然存在的绑定为前提。

每次输入、结果投影及每个出站项目发送前，重新检查当前绑定和 Agent 使用权限。解绑先提交授权撤销，再取消旧会话和清理旧投影；清理只针对失效代次，不能误删并发创建的新绑定。停用通道、更换凭据或失去 Agent 使用权限，也会使观察者停止；恢复扫描会取消其余失效会话。

旧版不带凭据范围的配对不会自动升级，部署后需重新配对。凭据轮换也要求重新配对。查看和删除已有配对只要求有效登录；签发新码仍要求 Agent 使用权限。本功能不改变 TAPP 的声明、批准或授予权限规则。

## 执行与订阅各自管理生命周期

会话锁只负责串行准入和状态转换。接纳 Work 后，观察与投递在独立任务中进行；等待模型、任务或平台重试时不持有会话锁，因此 `/status`、`/stop` 和 `/new` 可以进入。

显式停止会中断已登记的执行 future，包括任务创建前的排队与规划，并取消已有任务、待确认操作及待投递结果。网络断开或用户转移注意力不等于停止。已经提交给外部服务的操作无法通过中断 future 撤销。

续答调用既有的 answer/confirm API，不把回答当成新指令。继续执行期间的事件同时进入原有等待链和当前续答 run；完成载荷若仍为 `waiting_for_input`，从任务的 `pendingQuestion` 恢复下一问的任务 ID、问题 ID 和选项值。启动前的同步失败保留原待答。

## 投递与恢复保证

一个出站记录包含有序的文本块、图片和当前下标。结果投影在同一事务内写入出站记录、待答状态和已消费的 run 事件序号。逐项收到平台成功响应后才按 run ID 和原下标做条件更新；停止或切换任务后晚到的回执不会重新创建记录或覆盖下一轮。暂时失败重试当前项目，不重新调用 Work。图片没有被省略在持久化记录之外。

恢复扫描重新附着已有、属于该用户的 run，并先处理待投递结果。即使 run 历史已过期，已经投影的出站记录仍可独立重试。它不会通过重新发起 Work 来补偿丢失的消息。

外部发送与本地数据库无法组成一个事务。平台已接受消息但响应丢失，或成功响应后数据库未保存下标，仍可能重复当前项目；这里不承诺 exactly-once。run 事件自身采用既有的异步持久化，尚未落库的事件在进程崩溃时仍可能丢失。投递故障时结果保留两天，用户可以用 `/stop` 结束重试。

飞书入站图片必须保留来源消息 ID，通过消息资源接口读取；仅有 image key 不足以下载用户发送的图片。QQ 出站会重新取得当前有效 token，不能沿用最初入站时缓存的短期 token。

## 部署范围

生产 `web` 进程承载 Work 与通道；`federation-worker` 只承载联邦，不能接管这些会话。当前通道准入锁和执行句柄位于单个 Work 进程，适用于当前单 web 实例部署。多 web 副本同时运行 bot 消费者尚不受支持：需要独立的通道消费者所有权、可续期租约及跨进程取消协议，不能只依靠入站消息去重宣称安全扩容。

## 验证

`myriad-agent-rules` 的 channel 测试覆盖解析、交互规则和任务绑定按钮。后端测试覆盖待答投影、逐项消息序列和执行取消。`channel_pairing/binding.rs` 中的忽略测试可使用临时 PostgreSQL 验证实际配对、别名、撤销、跨用户重新绑定及凭据轮换：设置 `MYRIAD_CHANNEL_TEST_DATABASE_URL`，数据库名必须以 `_channel_test` 结尾。该测试会清空这个专用测试库中的测试表，禁止使用业务数据库。

真实平台的凭据授权、消息资源权限和实际送达仍需在部署环境联调；本地测试不会向真实账号发送消息。
