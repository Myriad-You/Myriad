# 宿主密钥首期只支持静态请求头注入

Status: accepted

宿主密钥首期复用现有 credential binding：TAPP 声明固定 HTTPS 端点、请求头名和可选前缀，宿主后端在发送请求前注入密钥。密钥不能进入查询串、请求体或沙箱，本期也不实现 HMAC、AWS SigV4 等动态签名；这些能力需要独立设计后再扩展，不能由执行者从「平台代用」自行推导。

## Considered Options

**首期就支持模板变量注入（含查询串、请求体）。** 覆盖面大，但把密钥扩散到更多载荷位置，泄露面与审计面同步放大；模板解析还需同时认识宿主密钥与应用凭据两套前缀，复杂度叠加。首期没必要为少数需要查询串密钥的服务买单。

**首期就实现动态签名。** HMAC、AWS SigV4 是逐请求的密码学运算，与「静态塞一个 header」是两种安全模型，各自有独立的契约与错误面。把它们和静态注入一起做，等于把一个未定型的设计塞进首期，任何一处边界不清晰都会拖垮整条主线。

## Consequences

首期只覆盖 Bearer token、API key 等能放入固定请求头的第三方鉴权。要求查询串密钥、请求体密钥或逐请求签名的服务不在本期支持范围内。
