# 删除旧权限枚举后，已装应用的历史权限清空并标记需重新授权

Status: accepted

ADR 0013 决定直接删除旧粗权限枚举，但只覆盖了声明层（新装时 manifest 校验拒绝）。权限三层分开落库——`tapps` 表的 `manifest`（声明）、`approved_permissions`（批准）、`granted_permissions`（授予）。已装应用的后两列里存着旧权限字符串（如 `"media:control"`），删除枚举后这些值无法再解析，读回即失败。

决定：升级时迁移——把 `approved_permissions` 与 `granted_permissions` 两列里的旧权限串显式清除，并把受影响的应用置为「需重新授权」状态，升级说明中告知站长。

## Considered Options

**迁移时把旧权限串映射成对应新权限。** 等于把兼容映射搬进迁移，与 ADR 0013「直接不适配」自相矛盾——同一个决定一会儿说不做映射，一会儿又在迁移里做一遍。

**清空但静默。** 应用还装着，相应能力悄悄没了，正是 ADR 0013 明确禁止的「静默降权」。

**迁移删除依赖旧权限的应用。** 太重。权限变了，应用本体没变，卸载是超出权限变更语义的惩罚。

## Consequences

新装与旧装两头都显式：新装拒绝旧 manifest 并告知替代权限名；旧装清空旧权限并标记需重新授权，撞墙撞得明白。

「需重新授权」的具体落库表示（状态字段还是标记列）属于实现层，但「显式清除 + 标记 + 升级说明告知」三者缺一不可——缺了标记就是静默降权，缺了告知就是扩权/降权不明。
