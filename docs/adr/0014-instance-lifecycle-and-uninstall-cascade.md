# TAPP 生命周期：实例层三状态，卸载从安装层向下级联

Status: accepted

平台此前在术语层区分「暂停」与「暂存」，而在代码层把「用户看不见」处理成两种截然不同的结果：切 Tab 与窗口最小化保留沙箱并发出 `lifecycle:pause`，滚出视野与数据刷新则直接卸载 iframe。同一类用户行为——注意力转移——落到两种结果上，应用无法预期自己何时会失去状态。

决定：实例层只有三个状态——**运行 / 隐藏 / 销毁**。安装层的**卸载**是一条独立转移，它向下级联销毁该应用的全部实例。

## 隐藏只有一个状态，不再区分暂停与暂存

原术语表把「沙箱留在原地被通知停止」（暂停）与「沙箱被移出视图但存活」（暂存）分成两个词。这个区分在浏览器里不成立：**iframe 一旦被移到另一个父节点，浏览器会强制重新加载它**，等于销毁重建。因此「移出视图但存活」只能实现为「留在原地用样式藏起来」，与暂停的实现完全一致。浏览器不允许两者存在实现差异，术语表因此不再分列。

早前 ADR（0005、0006、0007）中的「暂存」一律按「隐藏」读。「暂存池」保留为持有隐藏实例的那个组件的名字，不是独立于隐藏的第四种状态。

隐藏是页面内的概念。小组件 iframe 活在路由视图内（`Home` 等），切换路由会被 React 卸载，因此「切页 → 隐藏」在现有架构下不成立。跨页状态保留由 App 级的 headless 常驻（`TappBackgroundRunner`，无 iframe、只有后台 core）承接，不需要也不应该把 iframe 宿主提升到路由树之外再造一套跨页视觉沙箱。

## 销毁是白名单，白名单外一律隐藏

判断标准只有一条：**授权前提是否已消失**。用户注意力转移从不属于授权前提消失。

销毁只发生在：卸载 TAPP、代码更新（资源代际提升）、登录态变更、权限变更、恢复时发现授权前提已消失、暂存池按容量或空闲超时淘汰。

滚出视野、切 Tab、窗口最小化、数据刷新全部走隐藏。切换页面不在隐藏之列——页面内沙箱随路由卸载而销毁，跨页状态由 App 级 headless 常驻承接。

## 卸载先销毁实例，再清资源

顺序不可颠倒，否则还活着的沙箱会去读已被删除的存储。卸载必须先销毁该应用的全部实例（运行的、隐藏的、后台存活的），再清除存储与注册资源，最后从安装列表移除。

## Consequences

`lifecycle:pause` / `lifecycle:resume` 已经存在，由 document 可见性与宿主 `paused` 合成为单一信号流，页面型沙箱已接线。缺口是小组件离屏路径把这个信号拿去做挂/卸判断，以及数据刷新用重建 iframe 实现——两者都是在既有机制上接线，不是新建机制。

卸载此前没有下达到沙箱：正在挂载的实例靠安装列表重载后自然消失，不是被卸载销毁的。把它变成显式级联是本决定里唯一的新建路径。

隐藏实例不会无限累积——容量与空闲超时由暂存池负责（ADR 0006），具体阈值另定。
