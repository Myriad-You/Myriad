# 暂存池对停止实例用淘汰控制、对运行实例用准入控制

Status: accepted

暂存池同时持有两类实例：已停止的暂存实例和仍运行的常驻实例。两者的回收方式不能套同一套规则——停止的实例事后淘汰即可，运行中的实例必须在申请那一刻就决定是否准入，否则「答应了又反悔」比「一开始说不行」更糟：应用已经按「我会一直运行」安排了后续行为。

决定：**停止实例用淘汰控制**（容量满淘汰最久未露面 + 空闲超时）；**运行实例用准入控制**（名额满时在申请那一刻拒绝，绝不先答应再回收）。

## Considered Options

**运行实例也并入淘汰控制。** 语义最统一，但意味着平台可能在应用运行时毫无预兆地回收它，常驻声明的核心诉求（别停下我）被破坏。

**不设名额，运行实例无限累积。** 声明了常驻的应用可以无上限地占用实例，暂存池的容量控制对它们失效，是可被滥用的口子。

## 常驻资格分三档

- **事实维持**（媒体、文件传输）：工作经平台通道，播放器与传输记录都在平台手里，资格随时可验证 → 保持运行，工作结束自动降为普通暂存，**不占名额**。
- **名额准入**（通知、同步、事件监听）：工作发生在沙箱内部，平台只看得到黑盒、只能自报 → 走名额，获批后不因空闲回收。
- **不授予**（定时任务）：平台已代管触发，两次触发之间沙箱无需活着；仅当任务声明必须在前端执行时才落入名额准入档。

## 名额上限

每应用一个，全站再设一个总额，防止单个应用吃光名额。按声明理由分池被否——三类消耗的是同一种资源，分池只会鼓励应用挑空池子填。

## Consequences

无法保证永不退出。浏览器内存压力不在平台控制内；授权前提消失（登出、权限变更、代码更新）必须销毁；用户卸载也是出口。能做的是给「看不见却活着」一个可见出口——这一点的具体形态另议，不由本 ADR 决定。
