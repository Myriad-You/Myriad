# 宿主密钥缺失时一律 fail-fast，首期不做降级模式

Status: accepted

ADR 0003 要求声明了宿主密钥的应用同时声明降级行为，但「降级」至少有三种互不兼容的含义：不带鉴权头继续请求同一端点、改调另一个 fallback 端点、或返回受限的空结果。留着这个词等于让执行者自行发明协议。

决定：首期取消 `onMissing` 声明，宿主密钥缺失时行为固定——不向第三方发出请求，向 TAPP 返回单一稳定错误码 `HOST_SECRET_UNAVAILABLE`。密钥未配置、该应用未获授权、授权已被撤销三种情况返回同一个错误码，不透露是哪一种，也不透露密钥是否存在。

## Considered Options

**缺失时不带鉴权头继续请求。** 某些第三方接口在无鉴权时会返回匿名低配结果，看似有价值；但应用无法从响应中区分「拿到了受限数据」和「密钥没生效」，会把降级态当正常态跑下去，正是 ADR 0003 想避免的「静默跑成未知状态」。需要匿名访问的应用可以另外声明一个不绑定密钥的端点，由应用自己决定何时调用。

**缺失时改调 manifest 声明的 fallback 端点。** 一个逻辑调用背后出现两个出站目标，端点目录的鉴权、限流、审计和 origin 固定校验都要成对处理，代价远超收益。

## Consequences

现有执行路径已经是 fail-fast（凭据未解析即终止请求），本决定把它固定成契约而非实现细节，manifest 不再需要 `onMissing` 字段。

代价是应用无法表达「没有密钥也想跑」的意图，只能通过声明第二个不绑定密钥的端点绕过；这个绕法是显式的，因此可被审计。
