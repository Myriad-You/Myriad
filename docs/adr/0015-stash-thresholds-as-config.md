# 暂存池阈值作为平台配置项，附默认值

Status: accepted

ADR 0006 定了暂存池的两种控制机制（隐藏实例用淘汰、常驻实例用准入），但没有数字。本决定把数字定为平台配置项，由站长在管理面板调整，而不是前端硬编码常量。

## 四个配置字段

| 字段 | 类型 | 默认值 | 控制机制 |
|-|-|-|-|
| `stash_hidden_capacity` | i32 | 8 | 同页内最多保留几个隐藏（离屏）iframe，超出淘汰最久未露面者 |
| `stash_hidden_idle_seconds` | i32 | 300 | 隐藏实例离屏多久后被销毁——「滚出去多久字还在」 |
| `resident_quota_per_app` | i32 | 1 | 一个应用最多几个 headless 常驻实例 |
| `resident_quota_site_total` | i32 | 3 | 全站所有应用加起来最多几个 headless 常驻实例 |

字段落在 `DynamicConfig`，类型与先例 `user_ai_daily_calls` 一致（i32），默认值随结构体 `default()` 提供。

## Consequences

新增配置字段触发 ADR 0001 与 ADR 0004 的硬约束：每个字段必须同时补上从数据库读回的解析分支，一致性测试断言结构体每个字段都有解析分支、豁免项写明理由。AI 配额六个字段漏过一次就是前车之鉴——漏得完全静默。

选配置项而非常量的代价：改动不再是「改一个值」，而是走完整的新增配置流程（结构体字段、默认值、解析分支、一致性测试、seed）。收益是站长能按自己的设备内存与使用强度调整——暂存阈值是资源管理参数，个体设备的差异真实存在，硬编码会让小内存设备也被迫按大内存设备的阈值跑。

四个默认值是按用户故事行为尺度推导，不是内存实测，`uncertain`。配置化的好处正在于此：实测后改库值即可，无需发版。
