# Merope 2.5D 形象管线

## 目标与边界

形象是全站唯一的上半身 2.5D 角色。立绘必须让左右袖口或局部手臂自然进入画面，但不要求手或完整的肩—肘—腕—手形体；运行时也不提供这条关节链或腿部骨骼。左右手臂片分别作为 `a25d-handwear-left/right` 刚性整层挂在共享 `handwear` 父节点下，动作与运行时合成后的角度都限制在相对静止位 ±15°。共享语义契约仍只暴露 `root`、`torso`、`head`、`face`、双眼、嘴和 `handwear`，避免把资产侧刚性片误当通用肢体 API。

主立绘、PSD 内容画幅、Rig IR 画布和运行时相机统一为竖向宽:高 `3:4`。标准生成像素是 `1152×1536`，标准 Rig 画布是 `1×1.3333333`。形象生成只出这一张主立绘，透明图层与拆层由后续 See-through / 人工 PSD 完成。

当前 Agent 设定二级页使用五步链路：词条、命名、人设、角色视觉、主立绘。进入人设步时自动开始生成。第 4 步同一页选服装风格并写补充细节，用示例图帮助理解，然后才生成设计单；站长可以改字段、继续补要求或换一批。第 5 步进页后自动出主立绘，再用对话微调光线、表情和构图。只恢复能力，不恢复 v2 已废弃的异步素材 job 或 snapshot 状态机。视觉设计由后端读取已经落库的人格后生成，但只把气质、喜好和驱力交给模型，不送简介、社交方式或说话方式。界面语言、性别和服装类型都由本次请求显式提交，后端不从旧 profile 静默回退；界面语言也不能替用户选国风或和风。设计单拆成 `character`（脸、眼睛、发型轮廓与分层）和 `outfit`（上半身轮廓、服装结构、袖型/局部手臂、材质、标志饰品、配色、母题）两块；确认后整份冻结。换装只重写 `outfit`，不改脸和头发；换装请求只发送规范化后的人物模块，不再把旧服装作为新服装的锚点。外观补充要求改变时则重新设计完整人物。词条、名字、性别、人格补充或已确认人格改变后，旧视觉身份必须显式清空，不能被 partial merge 恢复；只有依赖上下文未变且调用方确实省略视觉字段时才保留旧设计。女、男、非二元和未指定分别约束脸部读取、眉睫、上半身轮廓与服装剪裁。主立绘再次携带同一个性别硬约束，性别进入 portrait generation contract 和 fingerprint；缺失或非法性别会在视觉设计或主立绘入口直接失败。未确认完整设计时主立绘接口拒绝生成。画风限定是最高要求：文本设计和图像提示共享米哈游式角色设计语法与参考图式的明净粉彩渐变完成度，但不照搬参考图的身份或粉紫配色。母版固定短中庭、紧凑圆润至柔和锥形的下半脸、小而简洁的鼻唇、中等偏大眼睛和大面积分层虹膜；`character` 只能在这个母版上做有限小改，脸部只微调圆润/锥形程度、眉形、眼睑、睫毛与默认嘴型，眼睛占比和虹膜尺度不能被重新设计。眼神通过视线方向、上下眼睑、眉眼张力、瞳孔聚焦和高光形状/位置形成可在缩略图辨认的角色差异；发型只改变颜色、长度、分缝、外轮廓和大块分组，发束构造与渲染仍归画风锁。原始外观补充在进入视觉设计模型前先按本次独立性别字段消解“女性 + 少年感 / 粗短平眉”等矛盾，再修正旧的越界脸型/眼型词，并移除画风覆盖和提示词覆盖片段；新设计若缺少明确性别读取、仍带相反性别线索或越出脸眼范围则直接判废并重试。已有旧设计和人工小改在落库、拼接图片提示及计算 fingerprint 前使用同一套规范化，越界脸型、眼型或画风描述不会进入图片提示。头发按大块前发、侧发、后发和宽发束组织，只用少量飞发；线稿纤细并随局部颜色变化；服装以清楚的分层剪影、配色分区、一个主饰品和两三个呼应饰品组织；皮肤与布料用柔和珠光正面光和受控渐变，眼睛、发丝光带、金属与宝石才用清晰硬高光。配色允许粉彩或深色，但必须明净、彼此可分，不能灰脏或单色糊满头发、衣服和饰品。允许参考原神 / 星铁的角色设计语法，禁止复刻现有角色的脸、服装、徽记或名字。正面近景、3:4 和干净浅色背景只服务拆层，不能把光影、发量和装饰密度压成证件照。不把它误写成扁平双色赛璐璐、粗黑描边、Q 版、游戏内 3D toon/NPR、半写实厚涂、油画皮肤或真人比例。

画风中的“米哈游式”必须落到可执行结构：图形化眼睫和眼睑、平面化宽发束与设计光带、明确领口和胸部焦点架构、几何裁片与接缝、分离色块、材质边缘差异，以及两至三个明度面的赛璐璐—渐变混合。明净粉彩只保留为表现层，不能退化成均匀柔焦、喷枪水彩、泛光或低对比分色。初次主立绘生成必须把版本化参考 PNG 作为真实 `input_references` 传给图片提供商；参考图只拥有脸眼尺度、发束组织、线稿、色彩清晰度和赛璐璐—渐变表现，已确认视觉身份继续独占人物、性别、成熟度、发型发色、服装、配色、母题和饰品。参考图摘要不能代替二进制图片输入。画风版本和参考图 SHA-256 都进入 generation contract 与 fingerprint，替换任一项都会让旧立绘失效。主立绘相机固定为视平线居中、零偏航、零歪头、零俯仰的正面参考视图：双眼同高且透视尺度一致，鼻梁—人中—下巴—颈胸处于同一垂直中线，解剖肩线水平并保持均衡透视。已确认的左右眼睑开合、发型、服装和饰品允许左右不对称，但不得因此改变双眼透视尺度、旋转头身、倾斜解剖肩线或伪装成三分之四视角。

提示词按单一所有权消解冲突，不把两个来源折中拼接：画风母版拥有脸部包络、眼睛尺度、线稿、发束渲染、边缘层级与材质表现；构图母版拥有相机、姿势、裁切、画面占比和背景；性别拥有性别读取；服装类型语法拥有服装家族及合理的领口、门襟、袖型和材料拓扑；保留人物时旧 `character` 原样拥有四个人物字段；兼容的明确外观要求优先于人格联想；人格只补仍未确定的配色和母题。字段内部同样只允许一个所有者：脸部写稳定眉形，眼睛写眉眼张力；发型轮廓写颜色和剪裁，头发分层只写分组遮挡；上半身轮廓、服装内部结构和袖型互不复述；材质不写颜色，饰品不重新定义母题，精确服装色名只在配色字段出现。换一批时旧设计只用于避重，不能被复制、合并或轻微换色。设计字段中的相机、构图、画风覆盖和提示词控制语句会在模型结果校验与成图前规范化两处拦截。

动作主线在分层 PSD 上由 Anime2.5DRig 的原版绑定/变形/微调驱动：呼吸、眨眼、角色轮廓自适应的单贴图口型网格桥接、独立的唇形与下颌轨迹、视线/转头视差、发丝双弹簧和胸腔跟随。导入阶段从五张口型的透明轮廓预计算桥接参数；另以一次视觉分析记录胸部表观大小、服装约束后的可见形变区域、支撑强度和外层传递程度，男性策略直接关闭该路径。胸部运行时以服装局部附着点为基底，以相对速度阻尼先同向跟随，并只在基底减速或转向后产生反向惯性回摆；表观大小控制基础惯性，服装支撑控制频率与阻尼，外层传递控制有界可见幅度，权重固定在静止网格而不随视角滑动。下颌只作用于嘴部网格和脸部嘴线以下区域，并用有界阻尼轨迹产生轻微回弹，不牵连头发、脖子或服装。现场播放不逐帧采样图像、调用 AI，也不以双贴图淡入淡出代替口型形变。页面、叠加层和设置仍是 Myriad 自己的界面。现场播放不再走骨骼蒙皮剪辑栈。

## 生产管线

```text
结构化设定 persona
  -> 上半身视觉设计候选 + 站长确认
  -> 独立 visual profile（character + outfit，展平后仍是 11 个视觉字段）
  -> character asset contract 快照 + fingerprint
  -> 1152×1536 主立绘生成
  -> 外部资产构建（See-through / Anime2.5DRig / 人工修图）
  -> 统一命名的分层 PSD
  -> 浏览器 ag-psd 解析、Anime2.5DRig 复刻绑定、契约预检、3:4 无拉伸补边、atlas 打包
  -> 后端 preview / migrate / diagnose
  -> 站长确认
  -> 激活带 contract version + source master id 的不可变 rig asset
  -> 公共页面读取 active manifest + atlas
```

## 人设与素材契约

`agent_persona.personality` 继续作为说话提示的兼容文本；`persona_json` 保存经过站长确认的结构化性格，`visual_profile` 单独保存性别呈现、服装风格、外观补充和拆成人物/衣装两块的上半身视觉设定。外观数据不能混进说话人格；修改普通人格文本不会改写视觉设定或让同一份视觉设定生成的立绘失效。

每次生成主立绘都冻结一份 `portrait_generation`：包含人物名、性别、规范化后的已确认视觉身份、主立绘尺寸、画幅、Rig 能力要求、画风版本、参考图哈希和成图微调，并对完整快照计算 fingerprint；同时记录实际 provider、model 和参考图角色用于追查。契约仍携带 `slot: "master"` 以兼容已有 fingerprint。说话人格、界面语言、词条、人设补充和视觉设计阶段的原始补充要求不参与外观提示词或立绘 fingerprint；原始视觉要求只在上一步解析一次，确认后的视觉身份才是唯一外观事实源。立绘步骤的用户输入只能微调光线、表情和构图密度；后端以正向范围词和越界词双重检查每个独立片段，拒绝含糊要求以及改变画风、人物、发型、服装、配色、饰品、姿势、视角、背景、性别或年龄的输入。编辑提示把来源图片当作不可变身份锚点，明确禁止重新规范化或重建脸部，也不能覆盖系统的构图、手臂或干净浅色背景要求。`1152×1536 / 3:4` 是生成请求和显示基准，允许提供商做合理尺寸取整或产生轻微构图偏差，不作为重复的落库阻断门槛；结果只经过图片缓存共用的格式签名和大小安全检查。主立绘是可直接审阅的完成图，透明背景与图层边界由后续 See-through/人工 PSD 阶段负责。

生成开始前，后端在 `agent_persona.portrait_generation.pending` 上以人物名和完整 visual profile 为条件抢占数据库租约；它跨进程共享，异常请求十五分钟后可被替换。图片生成完成后只按租约 token、人物名和 visual profile 条件更新立绘字段，不回写整份旧 persona 快照，因此生成期间的人格编辑不会丢失，视觉设定变化则使旧结果提交失败。立绘字段与 active Rig 指针在同一数据库事务内提交；事务失败时只回收本次新建且尚未成为当前立绘的缓存文件。

PSD 导入必须同时提交当前 `characterAssetContractVersion`、`sourceMasterAssetId`，并在生成立绘存在契约快照时提交 `sourceGenerationFingerprint`。后端在预检和最终激活前各校验一次主立绘与 fingerprint，再要求 Rig 画布精确为 `1×1.3333333`；编译后的 manifest 继续携带完整来源。这样链路可以回答三件事：素材按哪版规则生成、来自哪张主立绘、是否仍与当前人物设定一致。

Rig 包身份由 atlas 像素与规范化 manifest 共同计算。纹理运行时 URL 不参与哈希，来源、分层、骨骼、动作和参数全部参与；动作编辑与迁移生成新的不可变包并原子切换激活指针，不得在旧 `assetId` 下覆盖 manifest。手动替换/清空立绘或删除 persona 必须清除激活指针；读取活动 Rig 时仍需重新核对当前主立绘、generation fingerprint、契约版本、标准画布和包身份，任一不一致只返回主立绘 fallback。

正式分层资产至少提供：独立 face、左右睁眼/闭眼、开口/闭口、前后发、topwear，以及左右袖口或局部手臂刚性片。闭眼和闭口优先用 PSD 里的独立图层；没有时按 Anime2.5DRig 补通用差分，并允许用「目 / 口」条微调位置。缺失睁眼、开口或双侧手臂片的 PSD 在 atlas 打包前直接失败；同一能力门槛还会在后端 Rust 编译入口重复校验，不能通过自制请求绕过。

Myriad 主后端不加载第三方模型、不启动 Python，也不承担 GPU 推理任务。它只接收已经生成的 PSD/Layer IR，负责 owner 鉴权、预检、编译、版本管理、存储和激活。资产构建失败不能影响 Agent 或站点运行。

PSD 进入正式资产前必须通过同一套预检：文档尺寸/位深/图层数校验、图层语义归一化、必需能力校验、语义内容画幅裁切、`3:4` 透明补边、atlas 打包、后端编译和迁移诊断。See-through 的左右 letterbox 不进入 rig 画布，`legwear`/`footwear` 不进入上半身资产。补边只扩展透明舞台，不能拉伸角色。任何外部生成器都不能绕过预检或直接覆盖当前形象。

## 外部资产构建边界

See-through 只是一种可替换的 PSD 来源。若未来需要自动化，使用独立 GPU 资产 Worker 或 CI 作业：输入主立绘，输出带来源版本和构建参数的 PSD/Layer IR，再通过 Myriad 的普通导入接口提交。主后端不得代理本地进程，也不得假装尚未接入的远程 Worker 已经存在。

在独立 Worker 真正实现并部署前，产品只显示 PSD 导入、预检和激活，不显示不可用的“自动生成”按钮。开发机不运行 See-through。

## 第三方项目边界

- **See-through**：可选的离线主立绘拆层来源，不进入 Myriad 主后端或动画运行时。
- **Anime2.5DRig**（[MIT](https://github.com/852wa/Anime2.5DRig)，Copyright (c) 2026 hakoniwa）：See-through / 人工 PSD 之后的自动绑定与运行时。绑定、变形和微调参数按该项目原样接入；Myriad 只提供自己的页面、叠加层和设置。页面上标明使用了该项目。骨骼蒙皮剪辑栈不再作为分层形象的现场驱动。
- **PNGAL**：动作编排、状态切换、自然随机性和应用层交互参考，不直接引入其全身骨骼假设。
- **E-mote / Live2D**：效果标杆，重点是参数化表情、头身联动和连续过渡，不以兼容其私有格式为目标。

## 动作调度研究约束

动作系统采用 SAIBA / BML 的职责切分：导演给表达意图，统一行为层负责资源冲突和七个语义时点，Anime2.5D 只实现已经排定的行为；渲染器不能反向发明语义动作，也不能让音乐、说话或贴纸表情绕过统一调度。这里参考的是 [Behavior Markup Language](https://www.ofai.at/~hannes.pirker/papers/kopp_etal_IVA_2006.pdf) 的规划—行为—实现边界，不要求兼容它的 XML 格式。

“像人在动”和“这个动作适合此刻话语”分开验收。[GENEA Challenge 2022](https://arxiv.org/abs/2303.08737) 与 [GENEA Challenge 2023](https://arxiv.org/abs/2308.12646) 都显示，人类相似度较高不代表动作与自身话语或对话对象匹配，常见客观距离也不能代替主观判断。因此不能用动作幅度、平滑度或节拍命中率中的任一项单独宣称自然；同一段回复必须做匹配动作与错配动作的成对观看。

节拍只决定动作何时落点，不决定该做什么。[ConvoFusion](https://openaccess.thecvf.com/content/CVPR2024/html/Mughal_ConvoFusion_Multi-Modal_Conversational_Diffusion_for_Co-Speech_Gesture_Synthesis_CVPR_2024_paper.html) 将语音节奏、文本语义、词级强调和对话上下文共同用于手势生成；Myriad 在没有完整手臂和手部链的前提下，把这条约束投影为表情、视线、头部、躯干和刚性袖片的协调，而不是伪造不可实现的手势。[EMAGE](https://openaccess.thecvf.com/content/CVPR2024/html/Liu_EMAGE_Towards_Unified_Holistic_Co-Speech_Gesture_Generation_via_Expressive_Masked_CVPR_2024_paper.html) 的整体协调作为效果目标，但其全身三维生成器不进入当前运行时。

实时性验收分成两段：已经知道的 TTS 重音、行为峰值和音乐节拍可以有限前视；指针、现场音量和次级物理只能使用已观察输入。预测不能改写已经承诺的动作峰值，也不能通过更大幅度掩盖语义选择错误。

## 验收

每个真实角色至少验证：静止呼吸无明显橡皮形变；眨眼与口型不拉扯头发/肤色；头身转动连续且服装轮廓不穿帮；发丝双弹簧与双眼 stencil 裁切可见；动作切换无跳帧。性能必须在真实 atlas 和真实动作混合下采集。没有分层包时 `/active` 只回主立绘地址，叠加层画静图，不再合成假的剪辑栈 manifest。

下一阶段按固定顺序推进，不再用程序生成的占位分层判断最终效果：

1. 选定一张 `1152×1536` 主立绘及其 generation fingerprint，冻结为第一套 golden asset。
2. 在外部 GPU 资产环境运行 See-through/魔改拆分器，人工补齐双眼、嘴型、前后发、服装与左右手臂片，输出统一命名 PSD；开发机和主后端都不运行 See-through。
